# Algorithm Study Roadmap

This is a practice path, not a required implementation checklist. Mark a topic
complete when you can recognize it in unfamiliar problems, explain why the
approach works, analyze its complexity, and solve several variations.

Use this roadmap to track algorithm topics. Keep book-specific reading notes in
`notes/booknotes/` and implementations in `impl/`.

## 1. C++ and problem-solving fundamentals

- [ ] Fast input/output, types, integer overflow, and compiler diagnostics
- [ ] `vector`, `string`, `pair`, `tuple`, `set`, `map`, and `unordered_map`
- [ ] Sorting, custom comparators, binary search, and standard algorithms
- [ ] Complexity analysis, constraints, and choosing an approach

## 2. Core patterns

- [ ] Prefix sums and difference arrays
- [ ] Two pointers and sliding windows
- [ ] Binary search on values and answer spaces
- [ ] Greedy methods and sorting-based strategies
- [ ] Recursion, backtracking, and exhaustive search with pruning
- [ ] Bit manipulation and subset enumeration

## 3. Data structures

- [ ] Stacks, queues, deques, and monotonic structures
- [ ] Heaps and priority queues
- [ ] Hashing and frequency counting
- [ ] Disjoint-set union
- [ ] Fenwick trees and segment trees
- [ ] Tries and ordered search structures

## 4. Graphs and trees

- [ ] BFS, DFS, components, and cycle detection
- [ ] Topological sorting and directed acyclic graphs
- [ ] Shortest paths: BFS, Dijkstra, and Bellman-Ford
- [ ] Minimum spanning trees
- [ ] Tree traversal, diameter, lowest common ancestor
- [ ] Tree and graph dynamic programming

## 5. Dynamic programming and advanced topics

- [ ] One- and two-dimensional DP
- [ ] Knapsack, subsequences, and interval DP
- [ ] Digit DP and state compression
- [ ] Number theory: gcd, primes, modular arithmetic
- [ ] String matching and hashing
- [ ] Advanced range queries and offline techniques

## Practice loop

For each topic, solve problems from easier to harder constraints. For every
solution, note the key observation, correctness argument, complexity, and edge
cases. Revisit failed problems and implement a reusable template only after
understanding the technique it represents.
